## 断点怎么来的

一张卡的**宽卡形态**（卡头一行 + 副标题五轨同行 + 字段 2 列）最小 553px：

    内边距 32 + 边框 2 + 底板 40 + 列间距 10 + 副标题第一行 181 + 列间距 10 + 按钮组 278 = 553

其中 181 是副标题的 min-content（类型标轨 112 + 6 + 点槽 13 + 6 + 状态字 38），
278 是「打开 Web UI / 停止 / 重启 / ⋯」那一排的实际宽。两个数都是量出来的：
把卡片钉在递增宽度上，看哪一档 `.dsh-sub` 的 scrollWidth 首次等于 clientWidth
（实测 550 那一档归零，与上面的算式吻合）。

页面这侧的可变宽度 = 视口 − 侧栏 190 − 页面左右内边距 44 = 视口 − 234。于是：

    2 列：视口 ≥ 234 + 12 + 2 × 553 = 1352
    3 列：视口 ≥ 234 + 24 + 3 × 553 = 1917

上限就是 3 列（超宽屏不加列，卡片自己变宽）。列数用显式 media query 钉死，
不用 `repeat(auto-fit, minmax(553px, 1fr))` —— auto-fit 在超宽屏上会冒出第四列。

卡内自适应大多由 flex 自己算，不需要断点：卡头 `flex-wrap` +
`.dsh-ident { flex: 1 1 181px }`（放不下就把按钮组整组折到第二行，仍右对齐）；
副标题 `flex-wrap` + `.dsh-tail { flex: 1 1 160px }`（行内剩不下 160px 就把
尾轨折到第二行）。只有改常量本身的几条按视口给：

| 视口 | 卡宽 | 做什么 |
|---|---|---|
| ≤ 786 | < 553 | 字段塌成 1 列 × 6 行（窄卡形态） |
| ≤ 620 | < 386 | 内边距与类型标轨各收一档 |
| ≤ 460 | < 226 | 类型标轨整条收掉（pill 截到 0，完整文字仍在 title 里） |
| ≤ 400 | < 166 | 按钮组与字段标签允许缩（挤不下时按钮先折行，轮不到缩） |

## 一处要说清的取样限制

现网这一刻只有 1 只运行实例 + 2 张停止卡，而它们分属两个栅格，
所以**没有任何一格真的排满过 3 张卡**。1920 那档的第三个 x（1344）是这样量的：
在浏览器里把最后一张卡 `cloneNode` 一份追加进同一栅格，量完就 `remove()`
（只动内存 DOM，不碰服务端状态、不发任何动作），得 `[212, 778, 1344]`，
与 `grid-template-columns: 554px 554px 554px` 一致。截图
`3col-1920-with-injected-clone.png` 就是那一刻，`3col-1920-real.png` 是同视口的
真实页面（第三格空着）。
