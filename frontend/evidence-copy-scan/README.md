# 可见文案扫描：内部术语一个不留

判据只有一条：**这句话是给「用这个工具的人」看的，还是给「改这个工具的人」看的？**
后者不该出现在使用者读得到的地方 —— 收进更深的悬停层级，或者删掉。

起因：使用者打开详情抽屉，第一句评价是「有一说一，好乱哦」。
抽屉「状态」一节当时说了四遍同一件事（档位标签 + 技术散文 + 字段原文 + 后端原话整段）。

## 跑法

```bash
cd dsh-console/frontend/evidence-copy-scan
node scan-visible-text.mjs http://127.0.0.1:5390/ scan-after.json
```

## 扫什么

两样都算「可见文本」：

- 正文的文本节点（逐节点抓，命中能指到具体元素）
- 悬停与无障碍属性：`title` / `aria-label` / `placeholder` / `alt`

覆盖面：五个路由各扫一趟（总览 / 日志 / 设置五个分组 / 回收站 / 关于），
总览页再点开一张卡的详情抽屉扫一遍 —— 抽屉不在 DOM 里的时候扫不到它。

## 术语表（扫的就是这些）

| 命中名 | 正则 |
| --- | --- |
| `state=` 这类取值写法 | `state\s*=` |
| 字段名 | `stateReason` / `profileHealth` |
| 契约编号 | `成因` |
| 签名 id / 组件名 | `dsh-auth-401` / `dsh-boot-global` / `dsh-client-connection` / `dsh-console-api` |
| 实现视角的词 | `后端` / `接口` / `字段` |
| 请求路径 | `POST|GET /api/…`、裸 `/api/…` |
| 登记文件 / 请求头 | `runtime.json` / `X-DSH-Console` / `readOnly` |

包名（`@deepseek-ai/dsh-experimental-*`）**不在**术语表里：那是使用者真要读到的东西
（缺的就是这些包，profile 健康那一节要照着它去装）。

## 改前 / 改后

| | 命中 | 去重 | 位置 |
| --- | --- | --- | --- |
| 改前 `scan-before.json` | 27 | 19 | 卡片状态灯悬停、抽屉正文与悬停、日志页 |
| 改后 `scan-after.json` | 2 | 2 | 见下 |

剩下那 2 条都不是界面文案的缺陷：

1. **日志页那一行**：某个插件启动时打出来的路由表，是**日志内容**，不是我们写的字。
   扫描器只看文本，分不出「界面写的」与「日志里读到的」；验收时按内容排除。
2. **Web UI 按钮悬停里的 `runtime.json`**：这是后端给的「为什么读不到令牌」原话，
   整段都在悬停层级里（正文一个字不占），也不在本轮要清的清单里。
   要再干净就得回到后端改那句话的措辞，前端不替它编。
