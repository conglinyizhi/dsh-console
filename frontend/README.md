# dsh-console 前端（rabbita + precss）

四页全量：左侧导航四项（实例总览 / 日志 / 设置 / 关于），页面状态写进地址栏
（`history.pushState` + `popstate`，见 `route.mbt`），刷新与前进 / 后退都落回原处。
读数全部来自后端五个只读接口，读不到就照实写「未知」/「—」，不编；
**读数还没回来之前界面是加载态，不是空态**。

写动作走契约里的两个写接口：概览页**详情抽屉里的控制按钮** → `POST /api/local/action`，
设置页 → `GET/PUT /api/local/settings`（形状见 `../design/write-api-contract.md`）。
「设置」原先在顶栏，这一轮搬进侧栏并做成左索引 + 右条目的设置页，顶栏随之取消。

**依赖只有 rabbita 与 precss**：没有组件库、没有图标字体、没有仓库外的模块成员。
组件 DOM 与类名照 Vue 版（已按清单退役，见 `git log`）逐条对齐，样式与图标都是我们自己的。

Vue 版留下的对照物：`../design/vue-baseline-*.json`（几何基线）与
`../../dsh-console-design/`（三列对比图与换栈决策）。

`moon` 往里写不了 registry 缓存。要覆盖就 `MOON_HOME=... ./build.sh`。

## 目标平台为什么是 js

`moon.mod` 里 `preferred_target = "js"`，`supported_targets = "js+native"`（native 只给
`cmd/build-styles` 这个构建期步骤用）。理由三条：

1. **这一侧的运行期就是浏览器**。页面要自己 `fetch` 五个只读接口、自己渲染，
   native 目标给不了这件事。
2. **native 那一侧已经被后端占了**。`../backend/`（MoonBit + moonback）已经是同端口
   服务静态与 JSON 的进程，前端再出一个 native 服务就是两个进程抢同一件事。
3. **构建期的样式编译**（`cmd/build-styles`）要读文件、写产物，只有 native 给得了；
   它由 `build.sh` 用 `--target native` 单独跑，不进浏览器产物。

## 依赖：只剩 rabbita 与 precss

`moon.mod` 的 import 表就是全部依赖，三个都从 registry 解析：

| 依赖 | 谁在用 |
| --- | --- |
| `moonbit-community/rabbita` | 全部视图与 update 循环 |
| `conglinyizhi/precss` | 只在 `cmd/build-styles`（构建期把 SCSS 编成 CSS） |
| `moonbitlang/async` | 只在 `cmd/build-styles`：`async fn main` 语法与 `@fs` 读写都来自它 |

**没有 `moon.work`，也没有外部模块成员**：上一版把组件库以本地路径写进 `moon.work`
（它没发布到 mooncakes），代价是本工程不自包含。组件库摘掉之后这份工作区文件一起删了，
仓库自包含；`icons.mbt` 需要的图标路径也是取一次、固化成常量的，不留 Node 依赖。

想删 `moonbitlang/async` 之前先看这条：浏览器那一侧确实不用它（`app.mbt` 里的
`async fn` 是 MoonBit 的语言语法），但 `cmd/build-styles` 要，删掉会直接报
「its containing module is not imported by … cannot be imported by its package」。

### 另一个坑：本模块根包的别名要显式给

模块名 `conglinyizhi/dsh-console-frontend` 带连字符，`cmd/app` 里引自己的根包时，
默认别名会从最后一段推导、推出来的标识符不合法。必须写成：

```
import {
  "conglinyizhi/dsh-console-frontend" @frontend,
}
```

## 组件与图标都是自建的

卡片、按钮、徽标、对话框的 DOM 与类名照 Vue 版逐条对齐，形状全部出自 `styles/app.scss`
（那份表就是从 Vue 的组件样式块机械迁移来的）。没有组件库要对抗，也就不再有
「把 Material 的尺寸档掰回我们的值」那层覆写。

图标是**内联 SVG**，不是图标字体：

- 30 条路径固化成常量放在 `icons.mbt`，助手 `icon(name, size)` 产出
  `<svg class="dsh-icon" viewBox="0 0 24 24" width=… height=…><path d="…"/></svg>`；
- 尺寸在调用点上逐处给（12 / 13 / 14 / 16 / 17 / 20 / 26），与 Vue 版 `AppIcon` 的
  `:size` 一一对应。**别随手改**：侧栏图标大一号就会把「从当前实例派生开发副本」
  那行挤成两行（实测过）；
- 路径数据取自 `@mdi/js` 7.4.47 之后**固化**，Node 依赖没有进仓库；
  声明在 `vendor/licenses/mdi-NOTICE.md`；
- 所以 `dist/` 里没有任何字体或图标资源，只有 `app.css`、`app.js`、`index.html`
  和一份许可声明。

**不套现成组件，以及为什么**（这些是上一版逐个对比过的结论，仍然成立）：

- 抽屉 / 顶栏类组件把 `position: fixed`、`z-index`、side 偏移写成**内联样式**，
  而本外壳是文档流里的 flex 两列；内联样式没法从样式表压过，除非上 `!important`。
- 菜单锚在 activator 的包裹层上，位置由内联样式给；我们的不变量是
  「锚在按钮组容器上、top = 按钮组底 + 6px、right: 0」。
- 对话框内容是内联 `translate(-50%,-50%)`，遮罩不给点击回调；我们要「点遮罩关闭」，
  而 rabbita 的 `div.on_click` 收不到事件对象、判断不了 target。
  改成遮罩与卡片同级（遮罩 z-index 60、居中层 61），点遮罩天然成立。

## 样式：一份文件 + 自带的 reset

`dist/assets/app.css` 由 `styles/app.scss` 一份编出（`cmd/build-styles`，precss）。
文件内部按 **reset → 设计 token → 版式** 排；颜色、圆角、间距一律用 SCSS 变量。

**reset 必须自己带。** 这一层以前由组件库的 vendor 层提供，摘库的时候最容易漏：
清单里那些几何量（卡片 padding、字段行高 28px、侧栏 190px…）都是建立在
「所有元素 margin/padding 归零」这个前提上的，少一条整页就位移。
所以 app.scss 开头有一节显式的 reset，表单控件的浏览器默认皮也在那里摘干净
（原生 `select` 的箭头显式关掉：我们没画替代品，不关的话系统箭头会冒出来）。

**precss 不做颜色函数求值。** `rgba($ok, 0.1)` 会原样吐成 `rgba(#4ec27a, 0.1)` ——
浏览器认不了，整条声明被丢掉，背景/描边会静默回落成上一条规则的值（踩过：徽标的
`.real` 底色没了）。需要透明度时用 RGB 三元组变量：`rgba($ok-rgb, 0.1)`，
那几个变量在 app.scss 的 token 一节。

`app.scss` 是机械迁移来的：脚本按类名映射表把 Vue 版散在 18 个组件的 `<style scoped>`
改名前缀。迁移脚本没进版本库（一次性），映射表与自检在提交说明里有记录。

## 动效

唯一的动效是启动等待态状态点的 `dot-pulse`（900ms 呼吸 + 琥珀光晕）。
组件库自带的 transition（按钮背景/阴影、卡片 box-shadow、那条高度为 0 的 loading
进度条）随库一起去掉了，量「还有没有动效」时结果是 0。

## 写接口这一侧（这一轮新增）

页面上的动作不再是演示，全部落到契约里的两个写接口上：

- **行内按钮与下拉菜单** → `POST /api/local/action`，请求带 `Content-Type: application/json`
  与 `X-DSH-Console: 1`（自定义头就是契约里的跨源闸门，浏览器不允许跨源带它）。
  action 与 params 逐条按契约：`start-instance` / `stop-instance` / `restart-instance` /
  `fork-profile` / `rename-profile` / `archive-profile` / `unarchive-profile` / `delete-profile` /
  `set-profile-note`。
  `delete-profile` 在 `safety.deleteToTrash` 不是 true 时带上 `confirm:"DELETE"`。
- **设置页** → `GET /api/local/settings` 取当前值 / 缺省 / 来源，`PUT` 一次改一个键。
  改动即保存，成功失败都有反馈，失败显示后端给的 `code: message`。
- **成功率与失败率不一样对待**：动作成功之后重读 `profiles` + `instances`（刷新读数，不是弹个提示）；
  失败把后端的原因原样显示在总览页顶部的提示条上，不吞、也不伪装成成功。
- **目标来自读数**：读不到 profile 目录名或端口时，动作在本地说清「没有可用的目标」并不发请求 ——
  演示数据里的名字（main / dev / staging）不会被打到真实的东西上。
- **启动有等待态**：回执与展示下限（`start_delay_ms`）都到齐才收尾；收尾不伪造成「运行中」，
  真的起来了的那张卡由重读 `instances` 给出。

### profile 备注（第二轮）

每只 profile 可以写一条备注记它是干什么用的。备注在**它自己的目录里**
（`<profile 目录>/.dsh-note.txt`，契约里定的位置），所以改名、派生、搬走都跟着走；
前端只负责读写这条读数与那个动作：

- **读**：`GET /api/local/profiles` 每个 profile 多一个 `note`（与 `noteSource`）。
  非空时卡片**下面**多一行：只有备注本身（左侧一道细竖线当书签边，**不带「备注」标** ——
  这一行整个就是备注，标签是把同一句话说两遍），整行省略、完整内容与来源在悬停里。
  **没有备注的卡片不进这一行**（`note` 空串时那个节点根本不在 DOM 里），
  所以卡片几何与加这个功能之前逐项一致 —— 这条是量过的，不是估的。
- **写**：行菜单「编辑备注」（与「重命名」并列）→ 同一套对话框外壳
  （居中层 `.dsh-dialog-wrap`、Esc 取消、关闭后焦点回触发元素），内容是自由文本：
  预填当前备注、光标落在文末、留空保存就是删掉备注。
  **保存失败不关框**：后端给的原因（`bad-params` / `io-error` / `not-authorized`…）写在框里，
  改一改就能再存一次；成功了才关框、重读 `profiles`、提示条里给出后端那句 `note`。
- **删除确认框里也显示这条备注**：删之前能看清这一只是干什么用的（有备注才出现那一段）。

### 带令牌的访问地址（第四轮）

dsh web 的首次握手是 URL 里的 `?token=…`，不带就是一个 401 页面。控制台起实例时把 dsh 的
启动横幅（`dsh web: http://…/?token=…`）留在它的实例日志里，后端因此能按实例给出一个
**能直接握手的地址**：`GET /api/local/instances` 每条多 `webUrl`（读不到是 null）与
`webUrlSource`（令牌从哪来，或者为什么读不到）。前端这一侧只消费这两个字段，不自己拼地址：

- **打开 Web UI（卡上）与在新标签页打开（行菜单）用的是同一条 `webUrl`**。开没开成看
  `window.open` 的返回值：被弹窗拦截就写「浏览器把新标签页拦掉了」，不报一句空的「已打开」。
- **`webUrl` 为 null 时按钮照样可点，但一个标签页都不开**：提示条先说清读不到令牌的原因
  （后端那句 `webUrlSource`，例如「外部实例：令牌在启动它的终端里」），再把裸地址给人，
  让他从启动它的那个终端里抄横幅自己拼。拿裸地址去开新标签就是一个 401 页面，
  那等于给了个点了不能用的链接。
- **「访问地址」那一行显示的仍是裸地址**（人读的），悬停里说清带令牌的那条有没有、
  令牌从哪读来、读不到是为什么。令牌原值不进悬停：要看要复制走菜单。
- **两条复制**：「复制访问地址」复制裸地址；「复制带令牌的地址」只在真有 `webUrl` 时出现，
  复制的是 `webUrl`。剪贴板先走 `navigator.clipboard`，失败退到 `document.execCommand`，
  两条都失败就如实报失败（提示条上那句「已复制」必须对应真写进去的东西）。

真跑过的证据在 `../evidence-frontend-weburl/`：探针 `probe-weburl.mjs` 从页面上真点
（`Input.dispatchMouseEvent`，不是 `element.click()` —— 没有真手势 `window.open` 会被弹窗拦截），
抓 `window.open` 收到的原值、新标签的 target、剪贴板读回的内容，以及新标签自己的文档状态。

### 这两处读数从哪来

`runtime.json`（哪些实例是本控制台起的）与 `archive.json`（归档记录）是两份状态文件，
浏览器读不到文件系统。契约里那五个只读接口的形状一个字段都不动，所以后端另开了一个
只读端点 `GET /api/local/console` 把它们如实读出去，前端按这份读数办两件事：

- **卡片上的「由本控制台启动」**：按 `runtime` 里的 port 匹配，且那条登记的 pid 还活着。
  只看端口不够 —— 登记过、后来那个 pid 退了、端口被别人接走的情况长得一样。
- **归档区**：按 `archive` 里的记录标出对应的 profile 行，行上的归档时间就是记录里的
  `archivedAt`（显示成浏览器本地的 MM-DD HH:MM，原值留在悬停里）。磁盘上已经没有那只
  profile 的记录另补一行，好让人看见并撤掉它。**归档没有「已合并」标记了**（第二轮）：
  `archive[]` 里只有 `{ profile, archivedAt }`，旧文件里那个多余的字段读到时直接忽略。

这一份读数读不到不影响别的页面：卡片上少一个标记，归档区空着，其余照常。

## 页面状态进地址（第五轮）

地址是页面状态的第二个副本，不是另开一层：`route.mbt` 里一张表管两个方向 ——
`parse_route` 读、`route_url` 写，别处不许自己拼地址。

| 地址 | 页面 |
| --- | --- |
| `/` | 实例总览 |
| `/logs?source=…` | 日志（**来源是页面状态的一部分**：不带它，刷新就回默认来源） |
| `/settings` | 设置（第一个分组） |
| `/settings/<分组 id>` | 设置（某个分组，如 `/settings/safety`） |
| `/about` | 关于 |

- **为什么是路径而不是 hash**：后端静态服务带 SPA 回退（`backend/dist_static` 的
  `history_fallback` 指向 `/index.html`），`/settings/process` 这种没有对应文件的路径
  刷新时拿到的还是同一份 `index.html`，应用起来之后按 `pathname` 复原页面。
  **不用改后端**；换成 hash 也能落回，但地址里会永远挂一个 `#`。
- **写**：用户点出来的切换走 `push_route`（可后退）；由读数推出来的改写走 `replace_route`
  （回落、默认来源自动定下来的那一次），它们不是用户走的一步，不该在后退里多占一格。
  地址没变就不写 —— 同一页连点两次侧栏不该攒两条一样的历史。
- **读**：启动时读一次，之后每来一次 `popstate` 读一次**当前**地址
  （不是事件里那份，连点两次后退也只会读到最新的一条）。监听用一次性的 Promise 挂，
  回执进 `update` 再挂下一次，任何时刻只有一个在等。
- **认不出来的地址不白屏**：`/nope` 回落总览、`/settings/某个没了的组` 回落设置首页，
  并把「为什么」写成一句话显示在内容区顶部那条 `.dsh-route-notice` 上
  （回落这一步同时改写地址栏，页面与地址必须指着同一处）。
- 日志来源认不出（不是 `host` / `audit` / `instance:<id>`）也走同一套：按默认来源读 + 说一句。

### 读数没到 ≠ 没有数据

刷新之后那几百毫秒里，读数还在路上。以前这段时间界面直接摆空态
（「当前没有检测到正在运行的 dsh 实例」），把「还没读到」说成了「没有」。
现在分三档，且**三档互不混淆**：

| 档 | 数据源徽标 | 那一格 |
| --- | --- | --- |
| 请求还在路上 | `读取中`（`.dsh-badge.pending`）、分组计数写 `(…)` | 卡片栅格里是 6 块**与真条目同形**的占位块（**第十一轮起最多占一行**）+ 一行「正在读取…」（`.dsh-loading` → `.dsh-skeleton-row` / `.dsh-skeleton` / `.dsh-loading-note`）；日志页与回收站页仍是整幅一块（`.dsh-loading` 面板） |
| 读到了、确实是空 | `真实数据` | 空态（虚线框 +「当前没有检测到…」） |
| 读失败 | `演示数据 · 真实读取失败` + 具体原因 | 空态 + 那个徽标（既有行为，不并进加载态） |

- 判据是 `readings_pending(model)`（`built` 还没立起来）；日志页看的是
  `log_loading` 与 `log_source_read`：**内容不属于当前来源时显示加载态**，
  不拿上一个来源的行顶着新来源显示。
- 加载态**没有动效**：全页的动效留给启动等待态的状态点，
  多一个就会打破 `design/probe-animation.mjs` 的「点击前无可见动效」。
- 卡片栅格里的加载态**与真条目同形**（第八轮）：6 块占位（图标位 + 名字条）与真卡片共用
  同一套列轨与断点，占位块是静态灰块、不是交互元素，带语义的只有那一行 `role=status` 的说明。
  实测与口径见下面「加载骨架屏与卡片同形（第八轮追加）」一节与 `evidence-loading-skeleton/`。
- **第十一轮起每个分组最多占一行**：占位块装进一层 `.dsh-skeleton-row`，那一层横跨整幅、
  `max-height` 卡成恰好一行 + `overflow: hidden`，第 2 行往后裁掉（见下面第十一轮那一节）。
- 加载块的说明里刻意**不写**空态那两句话（「当前没有检测到正在运行的 dsh 实例」等）：
  验收是用整句去认空态的，加载块的说明里带上那半句，就会把「不是空态」这条判成假的。

路由与加载态的真跑证据在 `evidence-routing-loading/`（`node verify-routing.mjs <baseUrl>`）：
逐页 / 逐分组贴 URL、`Page.reload` 前后对照、前进后退、错误 path 的回落，
以及用 `Fetch` 拦截把接口压后 2 秒拍到的加载态 / 放行后的真实数据 / 空数组响应下的空态。

## 卡片第六格「最近改动」与已停止组的排序（第五轮追加）

使用者点出来两件事：① 卡片字段区是 2 列 × 3 行 = 6 格，却只填了 5 格，右下空着；
② 派生出来的 profile 排在列表最下面，看不出「刚弄出来一个」。

### 第六格：最近改动，不是创建时间

那一格取的是 **profile 目录的 mtime**（`GET /api/local/profiles` 的 `dirMtimeMs`，
毫秒时间戳），按浏览器本地时间显示成 `10-15 18:50`。

**口径是「最近改动」，不是「创建时间」** —— 这条要说清楚，不许含糊：

- 多数文件系统上**可靠的创建时间拿不到**。`ctime` 记的是 inode 变更时间，
  `chmod` / 改名都会把它推新，它不是出生时间；`birth time` 不通用
  （不是每个文件系统都存，也不是每个平台都读得到）。
- 目录 `mtime`（最近改动）是**能拿到、且不会骗人**的那一个。
- 它顺带回答了「哪个是刚弄的」：**刚派生出来的 profile 一定是最新的**。

所以：标签写「最近改动」，代码注释里也写「最近改动」。**任何地方都不许写成「创建时间」**✗

| 情况 | 那一格显示 | 悬停里有什么 |
| --- | --- | --- |
| 有值（停止卡 / 运行卡的 profile 解析得出） | `10-15 18:50` | 完整 ISO、口径说明、`dirMtimeSource` |
| 读了但读不到（字段是 `null`） | `读不到` | 后端给的 `dirMtimeSource` 原因，原样带上 |
| 运行卡解析不出 profile | `—` | 是「没解析出 profile 名」还是「profiles 读数里没有这一只」，分开说 |
| 响应里**根本没有这个字段** | `读不到` | 「profiles 读数里没有 dirMtimeMs 字段（后端这一版还没给）」 |

最后一行是前端补的话，与「后端读了但读不到」不是同一件事，所以要说得出区别 ——
**缺值不当 0，也不假装有值**。运行卡解析不出 profile 写 `—` 而不是「读不到」，
同理：没有可读的对象，和读了拿不到，不是一件事。

### 已停止组按最近改动降序

- 已停止那一组按 `dirMtimeMs` **降序**排：新的在最上面，刚派生出来的 profile 一眼就能看到。
- `dirMtimeMs` 为 `null` 的**一律沉底**（`None` 不是 0，不参与比较），同一档内按名字升序兜底 ——
  顺序必须是确定的，不然同一份读数每次刷新都可能换个样子。
- 运行中那一组不掺进这条口径：它还是按实例读数自己的顺序走。

**踩过的坑（记在这里免得再踩）**：兜底的名字升序**必须用 `String::lexical_compare`，
不能用 `<`**。MoonBit 的 `Compare` 对 String 是 **shortlex** —— 先比长度、长度相同再逐字符比。
于是 `"web-dev" < "headless"` 成立（7 < 8），三张卡按「名字升序」排出来是
`web-dev / headless / review-dev`，即「短的在前」，不是人说的字典序。
`evidence-mtime-field/probe-mtime.mjs` 的 DOM 实测把这件事抓出来了（那时页面顺序与接口对不上）。

DOM 实测的证据在 `evidence-mtime-field/`（真响应一跑、合成 fixture 一跑、缺字段一跑）：

```bash
node evidence-mtime-field/probe-mtime.mjs http://127.0.0.1:5390/ real evidence-mtime-field/real
node evidence-mtime-field/probe-mtime.mjs http://127.0.0.1:5390/ \
  synth:evidence-mtime-field/fixture-synth-profiles.json evidence-mtime-field/synth
node evidence-mtime-field/check-order.mjs evidence-mtime-field/synth.json
```

`check-order.mjs` 用 JS 的 `sort` 独立算一遍期望顺序，再跟页面上卡片的先后顺序对齐。
排序要在合成 fixture 上量：已停止组会排除正被实例用着的 profile，而机器上谁在跑是活的。

## 卡片变条目 + 详情抽屉 + 三色状态灯（第七轮追加）

使用者原话：「图标右上角来标记一个实心的圆，绿色标记为运行，黄色标记为故障，红色标记为停用」
「隐藏启动等一大堆按钮……首页就只有一点 profile 名称和备注等简单的东西」。

### 卡片只剩三样

三样各占一处：**左上** profile 名、**右上** 端口号（只在运行中那一条，写数字如 `3080`）、
**下面一行** 备注（有才进 DOM）。图标在左边，那颗实心状态灯挂在**图标**右上角 ——
与条目右上角的端口是两处位置，不是一处（见「第九轮追记」）。
六格读数、按钮组、行尾的 ⋯ 菜单**全部撤走** —— 点整张卡是打开详情的唯一入口。
卡片是 `article` + `role="button"` + `tabindex="0"`（不是 `<button>`：里面还可能放文本节点，
而 button 里嵌块级内容是无效的），鼠标点、Enter、空格都能开抽屉。

带走的东西一个都没丢，它们搬进了抽屉：**今天行菜单里有的一个不少** ——
打开 Web UI / 在新标签页打开 / 停止 / 启动 / 重启 / 查看日志 / 打开工作目录 / 编辑配置 /
重命名 / 备注 / 派生开发副本 / 归档 / 取消归档 / 复制访问地址 / 复制带令牌的地址 /
复制开发指令 / 删除，分四组（主操作 / 拿走 / 改动这只 profile / 运维）。
「由本控制台启动」那一枚也从卡片挪到了抽屉标题旁（它是第四样，卡片放不下）。

### 状态灯：三色 + 两档不是颜色的档

| 档位 | 颜色 | 判据 |
| --- | --- | --- |
| `running` | 绿 | 签名探测通过（后端的 `state`） |
| `fault` | 黄 | b：端口在听、持有它的进程像 dsh，但签名探测不通过；c：解析出的 profile 缺包 > 0 或没有 `cordis.patch.yml` |
| `stopped` | 红 | 没有在跑 |
| `starting` | 黄（在动） | 正在起来。同一支琥珀，但文案是「正在启动」，不会被读成故障；它就是原来副标题行上那个等待态的点 |
| `unknown` | **不上色** | 后端的 `state` 字段没给：空心灰环 |

**颜色不是唯一信息**（契约的硬要求），所以每一档都带两句话，读者不是同一个人：

- `light_reason` —— 抽屉「状态」一节里的正文：一行，说人话（`它正在 :3080 上应答` /
  `端口在听，但不应答 dsh 的握手` / `没有在跑`）。黄的两种成因因此分得开，两句长得不一样。
- `light_basis` —— 悬停里的技术依据：哪一条握手应答命中、探测回来的是什么、profile 那一侧怎么样。
  **正文一个字都不占**：成因编号、应答标识、组件名这些是给改这个工具的人看的，不进正文。

档位标签只说状态、不写颜色（`运行中` / `故障` / `正在启动` / `已停止` / `状态未知`）：
颜色由那颗圆自己给，文字里再说一遍就成了在念色卡编号。

**读不到状态时前端不猜颜色**：实例卡走 `unknown`（空心灰环），抽屉正文写「读不到状态，颜色不猜」，
已有的探测结论收在那句悬停里。理由是前端只看得到一半判据：绿的另一半（「端口在听却探测不通过」）
要后端把那些端口列出来才有，现在它们根本不进列表。**已停止的 profile 卡不一样**：它本来就不是
实例读数，黄/红的判据（缺包、有没有 patch）全在 profiles 读数里现成摆着，那是照判据算出来的事实。

读数里的 `state` / `stateReason` / `profileHealth` 按契约解析（形状见 `model.mbt`）；
其中 `stateReason` **不再直接渲染** —— 原文里有成因编号、应答标识这些内部名，
抽屉正文与悬停都由前端按结构化事实重写，原文留给将来给排查面板用。

### 详情抽屉

- 右侧、**覆盖式**（`position: fixed`，不占文档流，卡片不必为它让位）；遮罩与面板是**兄弟**，
  与既有对话框同一套做法（rabbita 的 `div.on_click` 收不到事件对象、判断不了 target）。
- 层级压在对话框之下（抽屉 50/51 < 对话框 60/61）：抽屉里的重命名 / 备注 / 删除会开对话框，
  框必须在抽屉上面。开这三个框时抽屉**先收掉**：不然取消之后焦点会落进一个盖在背后的面板。
- **点外部 / Esc / 关闭键**三条路都发 `DrawerClose`；打开时焦点进抽屉里的关闭键，
  关闭时焦点回**触发它的那张卡**（卡有稳定 id `dsh-card-<row.id>`）。
  焦点落在被卸载的节点上会掉到 body，键盘用户于是从页首重新 Tab —— 所以这一条是量过的。
- 窄屏（≤640px）占满宽度、宽屏固定 520px；内容自己滚（`.dsh-drawer-body` 的 `overflow-y: auto`）。
  窄屏下六格读数同时塌成一列（两列时值全被省略号截掉）。
- **开合有过渡**（第十一轮）：从右边滑进滑出 + 一点透明度，出入同一条 220ms / ease-out；
  收的那一段里节点多留一会儿、且对指针关掉 —— **焦点不等动画**，`DrawerClose` 那一拍就回卡片了。
  `prefers-reduced-motion: reduce` 下不做任何位移与淡入淡出（收的那一半连节点都不留）。
  见下面「开合过渡与骨架屏一行封顶（第十一轮追加）」。
- 列表重建后抽屉指着的那一行没了（实例停掉变成 profile 行、归档移出分组、profile 被删），
  抽屉自动收掉 —— 留一个没有内容的浮层会挡住底下。

### 响应式重算

卡片瘦成一行之后，原来那套「最小可用宽度 553px」的推导（副标题 181 + 按钮组 278）作废。
新的最小可用宽度 **240px** = 内边距 32 + 边框 2 + 图标 40 + 间距 10 + 名字那一格的可读宽度 150：
前四项是常量，150 是**可读性下限**不是溢出下限（名字与备注都带省略号，卡再窄也不溢出，
窄到 150 以下就只剩省略号、认不出是哪一只了）。运行中的条目还要从这 150 里分一点给
右上角的端口（4 位数约 30px + 一个 10px 间距，见「第九轮追记」）—— 卡到 240px 时
名字那一截还剩约 110px，仍认得出是哪一只。

| 视口断点 | 列数 |
| --- | --- |
| < 726 | 1 |
| ≥ 726 | 2 |
| ≥ 978 | 3 |
| ≥ 1230 | 4 |
| ≥ 1482 | 5 |
| ≥ 1734 | 6（上限） |

算式：页面这侧可变宽度 = 视口 − 侧栏 190 − 页面内边距 44 = 视口 − 234，
`n` 列要 `234 + 12 × (n − 1) + 240n`。常见宽屏的对比：**1280 从 1 列变 4 列，1920 从 3 列变 6 列**。
上限钉死 6 列（1920 上每张卡 271px；2560 上是 377px，不再加列）。
**任何宽度都不横向溢出**：页头那一行也允许折行（以前 `.dsh-head-note` 是 `flex: none` + nowrap，
360px 下会顶穿 `.dsh-main`，逐档实测抓到的）。

实测在 `evidence-card-drawer/`（探针一个都不改 `../design/` 的脚本）：

```bash
cd dsh-console/frontend/evidence-card-drawer
node probe-states.mjs  http://127.0.0.1:5390/ states  # 三色 + 黄的两个成因（计算样式，不是看截图）
node probe-drawer.mjs  http://127.0.0.1:5390/ drawer  # 卡片只剩三样 / 抽屉开合与焦点 / 按钮可达 / 窄屏占满
node probe-widths.mjs  http://127.0.0.1:5390/ widths  # 20 档宽度的列数与溢出
```

黄色的成因 b 需要一个「端口在听、cmdline 像 dsh、签名探测不通过」的进程：`fixture.mjs` 会真起一个
（`exec -a` 把 argv[0] 写成 dsh 的入口路径），并按契约把那条实例注入 instances 响应。
**这一版后端还不列这种端口**（`state` 已经落地，但「签名不过也列出来」这条行为还没有），
所以 b 是照契约造出来的；它的 `stateReason` 与真实探测结果逐字对齐（HTTP 200 text/plain，没有命中签名）。

## 加载骨架屏与卡片同形（第八轮追加）

使用者原话：「你正在加载的骨架屏和现在不太符合了，调整一下」。
第七轮把卡片瘦成条目（图标 + 状态灯 / profile 名 / 备注）之后，加载态还是宽卡时代那块
「整幅居中 + 一行字」—— 读数一回来卡片进场，主区宽度、列数、起始位置都要跳一次。

占位块里**没有端口那一格**：加载时还不知道哪一条在跑，摆一个假的端口位置只会骗眼睛；
高度仍是 70（端口那一格高 16 < 图标位 40，不进高度），所以放行后不跳。

现在加载态在**同一个栅格**里摆 6 个条目形状的占位块（图标位 + 一行名字条），与真卡片共用
同一套列轨与断点：外层 `.dsh-loading` 在 `.dsh-card-grid` 下是 `display: contents`
（不生成盒子），里面的块直接成为栅格项。**几何逐项对齐 `.dsh-case`**：内边距 14/16、边框 1、
圆角 10、图标位 40×40、图标与名字之间 10 —— 占位块高 70 = 没有备注的真卡片；
窄视口那一档（≤620px）两边一起收成 34 / 12 / 13，收到哪一档都对得上。

为什么是 6 块：栅格上限就是 6 列，宽屏那一档正好铺满一排，窄屏就是 6 行。
**这个数不是读数** —— 真有几张卡要等读数回来才知道，所以不假装知道；分组自己的高度因此
可能变（6 块占位 ≠ 实际 2 张卡），这是「还不知道」绕不开的代价，宽度与列轨不受影响。

| 视口 | 列数 | 占位块（加载时） | 真卡片（放行后） |
| --- | --- | --- | --- |
| 1920 | 6 | 271×70，列起点 212/496/778/1062/1344/1628 | 271×70；克隆到 6 张后列起点逐列相同 |
| 1280 | 4 | 252.5×70，列起点 212/476/742/1006 | 252.5×70，起点 212 |
| 768 | 2 | 261×70，列起点 212/486 | 261×70，起点 212/486 |
| 360 | 1 | 126×60，起点 212 | 126×60，起点 212 |

- 放行前后**主区宽度、列轨数、第一项的 x 逐像素相同**，宽屏下第一项的 y 也相同（96.7）。
  360 下第一项 y 从 227.2 变到 161，差的 66px **全部来自加载时那三枚「读取中」徽标**
  （页头 122.8 → 96.8、分组头 60.4 → 20.1，两项相加 66.3），与占位块无关，改之前同样存在。
- 占位块是**静态**的：加载态下全页在跑动画的元素 0 个
  （`probe-animation.mjs` 那条「点击前无可见动效」因此不受影响）。
- 占位块**不是交互元素**：`.dsh-loading button, .dsh-loading [tabindex]` = 0；点它的正中
  没有任何变化（URL / 抽屉 / 焦点 / 节点数全同）；Tab 走一圈焦点不落在它上面；
  12 块全部 `aria-hidden`，无 `role`、无 `tabindex`、无点击处理器，光标也是默认箭头。
  带语义的只有说明那一行（`role=status` + `aria-live=polite`，每个分组一处，文案只此一份）。
- 空态（`.dsh-empty` 虚线框）与「这一版后端没给字段」那两档**一个字没动**。
- 日志页与回收站页**照旧**是整幅一块：那两处的内容本来就不是卡片，条目形状在那里没有对应物。

```bash
# 用 Fetch 拦截把 /api/local/* 压后 2 秒：加载中那一刻量一次、放行后再量一次，

```

## 条目改两行与手动拖动排序（第十轮追加）

### 条目：左图标竖跨两行

第七轮的条目是一行（图标 + 状态灯 / 名字 / 右上角端口）加下面一行备注。第十轮改成**左图标 + 右两行**：
第一行是 profile 名与端口号，第二行是备注；**没有备注就写「上次启动」**，两个都没有就空着。

高度是这一版最要紧的一条约束。两行的行高加起来正好等于图标那一块的高度：
`22 (第一行 line-height) + 2 (body 的 gap) + 16 (第二行 line-height) = 40 = 图标`，
所以**有没有第二行，条目高度都是 70px**（`14 + 1 + 40 + 1 + 14`）—— 与第七轮「没有备注的条目」逐像素一致。
只有一行时整块由 `justify-content: center` 居中，名字的基线也落在原处。
响应式列数是从这个宽度推出来的，改 `.dsh-case` 的任何一条常量都要回头看 `.dsh-rows.dsh-card-grid` 那一段算式。
逐像素对照实测在 `evidence-card-layout/ab-old-*.json` 与 `ab-new-*.json`（同一份 fixture、改动前后两个构建）。

第二行有三档，各有各的记号：

- **备注**：左侧一道 2px 细竖线 + `$text-mid` —— 那道线是「这是人写的」的记号
- **上次启动**：`上次启动 10-15 18:20`，**不带那道线**、颜色再淡一档（`$text-dim`）—— 时间是机器的读数，
  给它挂上同一道线就是把两种东西说成一种
- **空**：不产出这一行（DOM 里没有节点），条目落回「只有一行」那副形状

时刻只从控制台自己的记录里取，取不到就空着，**绝不编一个时间**：正在跑的那一只用 instances 的 `startedAt`
（后端从进程起始时间推出来），其余按 `port:` / `profile:` 去 `GET /api/local/console` 的 `lastStarted` 里查
（后端把 `runtime.json` 的 `startedAt` 与 `audit.jsonl` 里成功的 `start-instance` 合成一份）。
解析不出时刻的串也当没有 —— 写一行「上次启动 —」看着像有读数，其实没有。

端口那一格的判据是「这一行知不知道端口」，**不是「灯是不是绿的」**：故障那一档里「端口在听、签名不通」
正是最该一眼看到「它占着哪个端口」的时候，拿颜色当开关会恰好把它藏起来。

### 拖动排序

全程**指针事件**（`pointerdown` / `pointermove` / `pointerup` / `pointercancel`），不用原生 HTML5 拖放：
后者的拖影与放下判定在无头浏览器里既验不了也不好控。

- **按下与点击共存**：按下只记住起点，位移超过 6px 才算拖动；没超过就还是点击（点条目开抽屉那条路一个字都没动）
- **落位提示**：目标那一侧画一道 2px 的 `$accent` 插入线（`::after`，画在盒子外面，落在 12px 的栅格间隙里），
  被拖的那一条淡一档
- **松手立刻写回**：`POST /api/local/action` 的 `set-row-order`，提交的是**整份新顺序**（不是增量），空数组 = 清空
  （成功的回执第十一轮压成「顺序已保存」，落盘路径与条数收进悬停，见文末那一节）
- **失败回滚**：写不进去就把顺序退回提交前那一份并如实报错（`io-error`），不停在「看着是新的、其实没存下」
- **窄屏不响应**：`< 726px`（单列那一档）里纵向拖动与页面滚动落在同一个手势上，按下即不启动拖动
- **键盘也能换位**：聚焦某一条之后 `Ctrl+↑` / `Ctrl+↓`，走同一条提交路径

指针的移动 / 松开 / 取消挂在**外壳**（`view_shell` 的 `.dsh-shell`）而不是条目或分组上：拖到列表之外松手时，
挂在分组上就收不到那一次抬起，拖动状态会一直挂着。另外移动事件带着按键位掩码，为 0 就当作「其实早就松手了」。

顺序表存在后端：`$XDG_STATE_HOME/dsh-console/order.json`，**按行 id 存**（`port:<端口号>` / `profile:<名字>`），
不存位置索引（列表本身会变）。生效规则：没拖过走自动排序；拖过用存下来的；表里没有的行按自动规则排在已排好的之后；
运行中与已停止**两组各自排**，不合并成一张表。

实测在 `evidence-card-layout/`（`drag-5533.json` 与同名截图：真指针按下一路拖到松开、落位线、写回后的 `order.json`、
刷新后仍在、窄屏不响应、写失败回滚、`Ctrl+↓` 换位），探针是 `../design/probe-drag-order.mjs`。

## 开合过渡与骨架屏一行封顶（第十一轮追加）

使用者原话：「加一点合理的过度效果：① 面板展开和折叠 ② 骨架屏每个分组最多占用一行空间」。

### 详情抽屉的开合

- 进：从右边滑进来（`translateX(100%)` → `0`）并淡入；出：往右边滑回去并淡出。
  **出入同一条时长与缓动**（220ms / ease-out）—— 一个快一个慢看着像被弹回去。遮罩跟着淡，
  但不参与滑。
- 时长写在两处、必须是同一个数：样式里 `.dsh-drawer` 的 `animation`，与 `state.mbt` 的
  `drawer_anim_ms`。**上限 300**：收的那一段走完之后节点才撤，验收探针在 Esc 之后等 700ms
  就断言「抽屉没了」，比 300 长就会让那条判定误报。
- 收的那一段由 Model 里的 `drawer_closing` 撑着：`DrawerClose` 把行 id 从 `drawer_id` 挪到
  `drawer_closing`，节点带着 `data-state="closing"` 多留 220ms 让滑出看得见，到点由
  `DrawerClosed(id)` 撤掉（**号对不上就不撤** —— 这中间又开过抽屉的话，那一枪作废）。
- **焦点立刻就走，不等动画**：三张卡上的老行为一个字没改（点外部 / Esc / 关闭键都发
  `DrawerClose`，焦点回触发它的那张卡）。收的这 220ms 里抽屉还在文档里，但已经
  `pointer-events: none`（半透明的面板不该再吃点击）—— 探针每 40ms 采一格，t=11ms 那一格
  就是「抽屉还在（`state=closing`，x=823.9）、焦点已在 `dsh-card-port-3080` 上」。
- **`prefers-reduced-motion: reduce`**：不做任何位移与淡入淡出。开的那一半由样式里那条
  media query 关掉动画（直接出现）；收的那一半还要求**连节点都不留**（留着的这段时间它还
  盖着页面），所以在 `DrawerClose` 里判一次（`dom.mbt` 的 `prefers_reduced_motion`）——
  那个设置下 Esc 是当场撤节点，采样第一格（t=10ms）抽屉就不在了。
- 新增的对外标记只有 `data-state="open|closing"`（动画与「对指针关掉」都挂在这个属性上）；
  可见文案：**无**。

### 骨架屏每个分组最多一行

- 6 块占位块照旧渲染，装进一层 `.dsh-skeleton-row`：**一条栅格项**（`grid-column: 1 / -1`），
  里面用与真卡片**同一套列轨**（五条断点写在同一个选择器列表里，不抄第二份）。
- 这一层 `max-height` 卡成恰好一行 + `overflow: hidden`：4 列时那 6 块本来排两行、2 列时三行，
  第 2 行往后直接裁掉 —— **不用在 JS 里量列数**，骨架屏也不会把下面的分组一路顶下去。
- 一行的高度就是骨架块自己的高：**70**（= 14 + 1 + 40 + 1 + 14，与 `.dsh-skeleton` 逐项对齐）；
  窄视口那一档（≤620px）两边一起收成 **60**，两条规则共享同一组数字（改一处得改另一处）。
- 读数回来之后高度仍会变（真卡片带备注就是两行）—— 这是使用者要的取舍；
  **列轨与宽度一个字都不变**（照上一轮的口径量过：列轨数、`grid-template-columns`、列起点逐列相同）。
- 360 那一档如实说一句：骨架块在这一档是 60（占位块的第二行高 8 < 真条目的 16，见第八轮
  「占位块永远不会比真条目高」），而带第二行的真卡片是 66。所以 1 列那一档的「一行」是 60，
  不是 66 —— 本轮只裁行数，不动块本身的形状。

| 视口 | 列数 | 露在外面的占位块 | 骨架区高 | 骨架块高×宽 | 真卡片高度（放行后） |
| --- | --- | --- | --- | --- | --- |
| 1920 | 6 | 6（第 2 行不存在） | 70 | 70×271 | 70 |
| 1280 | 4 | 4（另外 2 块被裁） | 70 | 70×252.5 | 70 |
| 768 | 2 | 2（另外 4 块被裁） | 70 | 70×261 | 70 |
| 360 | 1 | 1（另外 5 块被裁） | 60 | 60×126 | 66（带第二行）/ 60（不带） |

### 顺序保存那条回执

正文压成「**顺序已保存**」。后端那句原文是「`顺序表已写入 <落盘路径>（N 条）`」：
「顺序表」是内部叫法，落盘路径也不该摊在正文（与删除回执、设置页同一套口径）——
路径与条数收进悬停（`act_notice_hint` + `act_notice_hint_for`），一个字都没丢。
隔离实例里真拖一次读回来的是：正文 `顺序已保存`、悬停
`顺序表已写入 /tmp/dsh-console-fixture/state/dsh-console/order.json（4 条）`。

## 这一版没做的

- 归档区没有读接口（见上），所以它不是「真实的归档清单」，是本次会话的记录。
- 没有水合、没有 SSR。控件的交互都走 rabbita 的事件，不需要额外的 behaviors 脚本。
- `dist/assets/app.js` 1.61 MB（未压缩，gzip 约 188 KB）。后端不发 `Content-Encoding: gzip`，
  回环访问下可接受；构建链刻意不依赖 Node，所以没有加一道压缩步骤。
- 两个空态图标（运行中空态、已停止空态）本机有实例时走不到，只在源码层面核对过路径常量。
