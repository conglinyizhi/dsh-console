# 加载骨架屏与卡片同形：实测证据

第八轮。这里的每一个数都是 DOM 实测（`getBoundingClientRect` / `getComputedStyle` /
`elementFromPoint`），不是看截图认出来的。探针**只读页面**，没改 `../../design/` 下的任何脚本，
也没碰 `backend/`。

跑法（控制台在 5390 上跑着）：

```bash
cd dsh-console/frontend/evidence-loading-skeleton
node probe-skeleton.mjs http://127.0.0.1:5390/ skeleton
```

量法：`Fetch.enable` 拦 `*/api/local/*`，命中后压后 2 秒再放行。
导航后第 1.1 秒量一次（还在加载），放行 + 渲染完再量一次（真卡片），
四种视口各走一遍；`page-probe.js` 是注入页面的那一份量法。

## 一、占位块的几何与真条目

| 视口 | 列数 | 每格占位块 | 占位块 w×h | 列起点 | 真卡片 w×h | 卡片列起点 |
| --- | --- | --- | --- | --- | --- | --- |
| 1920 | 6 | 6 | 271×70 | 212 / 496 / 778 / 1062 / 1344 / 1628 | 271×70 | 212 / 496 |
| 1280 | 4 | 6 | 252.5×70 | 212 / 476 / 742 / 1006 | 252.5×70 | 212 / 476 |
| 768 | 2 | 6 | 261×70 | 212 / 486 | 261×70 | 212 / 486 |
| 360 | 1 | 6 | 126×60 | 212 | 126×60 | 212 |

- **宽度逐像素相同**：占位块与真卡片在同一个栅格项位置上，同一套 `minmax(0,1fr)` 列轨
  （列轨尺寸加载前后一致：`252.5px`×4 / `271px`×6 / `261px`×2 / `126px`×1）。
- **高度对齐的是「没有备注的真卡片」**：70（窄视口 60）。真卡片里带备注的那一张是 96（窄视口 86），
  多出来的 26 是备注行本身（间距 10 + 行高 16）—— 占位块按「图标位 + 一行名字位」这副最小形状摆。
- 占位块的盒子实测 `padding: 14px 16px`、`border: 1px`、`border-radius: 10px`、
  底色 `rgb(27, 29, 33)`（= `$panel`，与 `.dsh-case` 同色）；图标位 40×40、名字条 120×12
  （360 下随卡片一起收成 34×34 与 56×12）；光标 `auto`（真卡片是 `pointer`）。
- 列数用 `getComputedStyle(grid).gridTemplateColumns` 的轨道数 + 展开 `display: contents`
  之后的实际栅格项左缘来量（比数卡片可靠：本机只有 3 张真卡片，永远看不到第 6 列）。
  1920 那一档另把**真卡片克隆到 6 张**量了一遍：列起点 `212/496/778/1062/1344/1628`
  与占位块逐列相同，卡宽 271、卡高 70（`columns.sameXs = true`）。克隆只为量列轨，量完整页重载。

## 二、放行前后不跳

| 视口 | 主区宽度 | 列轨数 | 第一项 x | 第一项 y | 横向溢出 |
| --- | --- | --- | --- | --- | --- |
| 1920 | 1730 → 1730 | 6 → 6 | 212 → 212 | 96.7 → 96.7 | 无 → 无 |
| 1280 | 1090 → 1090 | 4 → 4 | 212 → 212 | 96.7 → 96.7 | 无 → 无 |
| 768 | 578 → 578 | 2 → 2 | 212 → 212 | 96.7 → 96.7 | 无 → 无 |
| 360 | 170 → 170 | 1 → 1 | 212 → 212 | 227.2 → 161 | 无 → 无 |

- **主区宽度、列轨数、第一项 x 四种视口全部逐像素相同**；宽屏（1920 / 1280 / 768）第一项的 y 也相同。
- 360 下第一项 y 差 66px，**全部来自加载时那三枚「读取中」徽标**（三档里的第一档，读数回来就消失）：
  页头 122.8 → 96.8（26.0，徽标让页头在 126px 宽下折行）、
  分组头 60.4 → 20.1（40.3，标题被徽标挤到折行），两项相加 66.3 —— 与占位块无关，改之前同样存在。
  占位块自己的 x 与 w×h 在 360 下也一个像素没变。
- 页面 / 栅格 / 主区三处 `scrollWidth > clientWidth` 全部为 `false`（八次量法共 24 处，全 `false`）。

## 三、占位块是静态的

加载态下全页扫描 `getComputedStyle(e).animationName !== 'none'`：**0 个元素在跑动画**
（`animations: { count: 0, names: [] }`，四种视口都是 0）。
`design/probe-animation.mjs` 那条「点击前无可见动效」的判据口径与此一致。

## 四、占位块不是交互元素

| 量法 | 结果 |
| --- | --- |
| `document.querySelectorAll('.dsh-loading button, .dsh-loading [tabindex]')` | `0` |
| 加载区里的 `button` / `[tabindex]` / `a` / `[role=button]` | `0 / 0 / 0 / 0` |
| 12 块占位块带 `aria-hidden="true"` | 12 / 12 |
| 带 `role` / 带 `tabindex` / 有 `onclick` 的占位块 | 0 / 0 / 0 |
| 页面上所有可 Tab 到的元素里落在加载区的 | 0（当时页面上可见可 Tab 的元素共 6 个：侧栏 5 项 + 「新建实例」） |
| Tab 走 12 次，焦点轨迹 | `dsh-nav-item`×5 → `dsh-new-btn` → `body` → `dsh-nav-item`×5（一次都没落在占位块上） |
| `Input.dispatchMouseEvent` 点第一块占位块正中 | 命中 `dsh-skeleton-name`（在块内）；点击前后快照逐字段相同：URL `/`、skeletons 12、cards 0、无抽屉、无遮罩、无对话框、activeElement `body`、栅格项数 `[1,1]` |

带语义的只有说明那一行（每个分组一处，共 2 处）：

```
<div class="dsh-loading-note" role="status" aria-live="polite">
  <p class="dsh-loading-line">正在读取实例读数…</p>
  <p class="dsh-loading-sub">实例与 profile 的读数还在路上。这里先摆加载态 —— 「确实一个都没有」要等读数回来才敢说。</p>
</div>
```

## 五、三档仍然分得清

- 加载中：分组标题写 `当前运行的实例 (…)` / `已停止的实例 (…)`，`.dsh-empty` **0 个**、
  状态灯 `.dsh-dot` **0 个**（占位块不是卡片）。
- 放行后：标题写 `(1)` / `(2)`，卡片 3 张、状态灯 3 颗，卡片里按钮 0 个。
- 空态（`.dsh-empty` 虚线框）与「这一版后端没给字段」（`trash-missing-field`）两档这次一个字没动。

## 七、这次没验的

- 「放行后卡片张数与占位块块数一致」不成立也不该成立：真有几张卡要等读数回来才知道，
  6 是「栅格上限正好一排」的固定值，不是读数。分组自己的高度因此可能变。
- 有备注的真卡片比占位块高 26px（备注行）：占位块按最小那副形状摆，读到备注就长一行。
- 只验了真实读数这一路；后端读失败时走的是空态 + 徽标那一档（`.dsh-empty`），这次没造那个现场。
