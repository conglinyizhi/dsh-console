# 设计清单修正（六条，按顺序做）

依据：ui-boot 包里的 ui-rules 与 checklist（2026-10-19 更新版）。每条都要在改完后用同一套量数复测。

## 1 状态灯补第二通道

问题：灰度下运行 0.416 与故障 0.431 几乎同一亮度，只靠颜色。
做法：总览卡片与配置侧栏的状态灯旁边补**文字状态**（运行 / 故障 / 已停止 / 试跑）。卡片高度最多 +2px；空间不够时把状态词放在第二行行首，与「上次启动 …」并列，格式 `运行中 · 上次启动 10-19 10:08`。
验收：灰度截图下三种状态可区分；文字状态在 DOM 里（data-state 旁边）。

## 2 中性灰补到 8 档

问题：现在实色中性灰只有 5 档，层级靠 alpha。
做法：在 SCSS 里立一组中性色阶（例如 `$gray-0 … $gray-7`，从页面底到最亮的文字），至少 8 档实色；页面底、面板、卡片、悬停、边框、次要文字、输入框底各取一档。少用 rgba 叠在白底上凑灰。
验收：量到的实色中性灰 ≥ 8 档；对比度不下降（低对比 0 条）。

## 3 空状态加行动号召

- 维护页空态：一颗 `开始一条作业`，点了把焦点送到「目标版本」那一格（或滚到表单）。
- 总览空态：一颗 `刷新读数`（现有动作）或把顶部「新建实例」的入口指出来，二选一，选能真点的那个。
验收：空态里有可点的按钮，点完有可见反应；按钮在灰度下也抢眼。

## 4 抽屉主按钮降一档

问题：抽屉里「启动」与「打开 Web UI」都是实心。
做法：「打开 Web UI」改次要样式（线框或低对比浅底），「启动」保持唯一实心；目标在跑时「打开 Web UI」成为主操作（那时没有「启动」）。一屏一个主操作。
验收：抽屉里实心按钮数在任一行状态下 ≤ 1。

## 5 1px 线减一轮

问题：总览 21 条、设置 28 条、关于 37 条 1px 线。
做法：优先用手上已有的灰阶（第 2 条）做底色差与留白分离；卡片与页面底之间、面板与卡片之间先删线；保留输入框、表头分隔、确认框边线。
验收：三类页面 1px 线条数各降三分之一以上（总览 ≤ 14、设置 ≤ 18、关于 ≤ 24），灰度下仍能分清区块。

## 6 关于页正文行高 1.7 → 1.8

验收：计算样式 line-height/font-size = 1.8。

## 19 收尾四条

### 19.5 验收

## 20 「从基础实例开始」：没有可用配置时的备用入口

前提：现有 profile 全坏、或全不可用时，用户仍要能建一只新的。做法是用 dsh 自带的基础模板新建一份，不依赖任何现有配置。

### 20.1 后端

动作 `create-base-profile`，参数 `{"name":"<名字>"}`：

1. 名字按既有规则校验（单段、只允许字母数字与 . _ -），已存在报 conflict；
2. 用已安装的 dsh 跑：`node <包目录>/lib/bin.js --profile <名字> --from-default-profile web --dump-config`，
   DSH_HOME 用控制台的 home，超时 60 秒；成功后退出码 0 且不会留下进程（已实测：只写 profile，不启动）；
3. 核对：`profiles/<名字>/package.json` 读得出、bundles 里有 `@deepseek-ai/dsh-web-app`、`cordis.patch.yml` 在；
4. 默认隔离（复用既有 isolate_profile）；隔离失败不影响建成功，回执照实说；
5. 任一步失败：删掉刚建的 profile 目录，回 io-error 并带 stderr 尾部。

回执：`已从基础模板新建 <名字>（已隔离到 <路径>）`。

### 20.2 前端

在「新建实例」对话框左下角加一颗**不显眼**的入口：文本按钮 `从基础实例开始`（低对比、无边框、字号比正文小一档），与右下角的「创建 / 取消」分开。

- 点它：把源切成「基础模板」，名字默认 `base-<两位序号>`（已存在就顺延），焦点进名字格；
- 选中后，「创建」调用 `create-base-profile`，不再走派生；
- 悬停说明：`用 dsh 自带的基础模板新建一份，不依赖现有配置。现有配置都不可用时用这个。`
- 没有可用 profile 时，这颗入口照旧可见可用。

### 20.3 文案（待审）

- `从基础实例开始`
- `用 dsh 自带的基础模板新建一份，不依赖现有配置。现有配置都不可用时用这个。`
- `已从基础模板新建 <名字>（已隔离到 <路径>）`
- 回执照实的两支：`已从基础模板新建 <名字>（隔离 home 没建成：<原因>，它与别的 profile 共用 DSH_HOME）` / 失败时后端原话

### 20.4 验收

1. 临时环境里：没有可用 profile 时，对话框里只有这颗入口可用；点它 → 名字预填 → 创建 → 新 profile 出现且 `homeKind=isolated`
2. 新 profile 能起实例（临时环境里真起一只，等到签名通过）
3. 同名已存在时报 conflict；名字非法时报 bad-params
4. dsh 跑失败（把包目录指坏）时，刚建的目录不残留
## 21 新建实例：基础模板改成复选框

把「从基础实例开始」那颗文本按钮换成复选框（标签同名），语义随之变成一种模式：

- 勾上：上面所有源配置卡**不可选**（置灰、aria-disabled、点击无反应），焦点落到名字输入框，旁边给一句引导 `填一个名字，它会用基础模板新建`
- 勾掉：卡片恢复可选，名字框**一个字都不动**（不还原、不清空）
- 名字框规则：勾上时**只有它现在是空的**才预填 `base-NN`；用户已经输入过任何字符（哪怕只有一个字）就不碰它。勾掉同样不碰。
- 判断「用户输入过」用一格脏标记：名字框的输入事件置位，预填不置位。
- 没有可用源时：复选框默认**勾上**（唯一可走的路），卡片照样置灰。

## 22 锁住源配置改成整片遮罩；note 去掉看不懂的那句

### 22.1 锁的方式换成祖先元素

勾上「从基础实例开始」时，不再给每张卡加 locked / aria-disabled / tabindex 那一套，改成：

- 源卡列表容器加 `inert`（整组不可聚焦、不响应事件）与 `aria-disabled="true"`；
- 同一容器上盖一层半透明遮罩（绝对定位、`inset: 0`、背景 rgba(0,0,0,0.42)），遮罩挡住指针；
- 遮罩中间或左上角给一句 `已勾上「从基础实例开始」，这些源配置这一刻不可选`（灰白小字，居中）；
- 列表保持原来的高度与滚动位置，不做隐藏与搬动；
- 勾掉：移除 inert 与遮罩，一切照旧。

卡片本身只保留读数带来的 `data-usable`，不再写 `data-selectable` / `data-locked`。

### 22.2 后端 note 收短

`create-base-profile` 的 note 里「没有留下进程」这句去掉，改成：

`用 dsh <版本>（<包目录>）自带的基础模板 web 新建；核对过三条：package.json 读得出、bundles 里有 @deepseek-ai/dsh-web-app、cordis.patch.yml 在；dsh 那一步用了 N 毫秒。<隔离那一句>`

### 22.3 验收

1. 勾上：列表容器有 inert 与遮罩；键盘 Tab 跳不进去；点卡片无反应；遮罩上那句在；高度与滚动位置不变
2. 勾掉：inert 与遮罩消失，卡片可点可选
3. 卡片上不再出现 data-selectable / data-locked
4. 建基础模板成功后的悬停里不再有「没有留下进程」

## 24 新建实例框三处：必填星号、卡片等高、勾选不再抖高度

### 24.1 名字是必填

- 标签「新实例名字（源配置：…）」前面加一个红色星号 `*`：`<span class="dsh-req">*</span>`，颜色用现成的 danger 色，`aria-hidden="true"`；输入框加 `aria-required="true"`，并在悬停里写「必填」。
- 星号不参与读屏报读（读屏靠 aria-required）。

### 24.2 源卡等高，原因只占一行

- 栅格里每张卡高度一致（`align-items: stretch`，行高由同一行最高决定但**每张卡都撑满**），卡片自身高度也钉死一档（例如 96px）。
- 不可用的卡：状态与缺包那一行照旧，原因那句（「这只配置起的是命令行型，没有网页入口」）**只占一行、超出用省略号**，完整句进悬停。
- 卡片内部纵向排布不留空洞：内容超出就裁，不许把卡撑高。

### 24.3 勾选复选框不许改对话框高度

- 名字格下面那句引导（「填一个名字，它会用基础模板新建」）改成**常驻占位**：没勾时这一行仍在，文字 `visibility: hidden`，高度不变。
- 勾上时列表上方的说明若也参与高度，同样改成常驻占位。
- 验收：勾上前后对话框总高度差 0；列表顶端与名字格顶端位置不动。

### 24.4 验收

1. 标签有红星号，输入框 aria-required=true
2. 1280 与 390 下所有源卡高度一致；不可用卡的原因只有一行并以省略号结尾，悬停里是完整句
3. 勾上 / 勾掉前后，对话框高度差 0，列表与名字格的位置差 0
4. 390 下同样成立；无横向滚动
## 25 配置卡片收敛成一个组件

问题（新建实例框截图）：列表里出现横向滚动条、卡片里「运行中 / 缺 6 个包 / 配置 home：共用」被折成两行、卡片塞的信息太多、框头那句说明随复选框切换变字。根子在于这张卡在四个地方各写一遍，改一处只修一处。

### 25.1 组件

在 `view_parts.mbt` 里做成一个组件（名字自定，例如 `profile_card`），四个地方全部改用它：

1. 新建实例框的源卡
2. 维护页「选择配置」（作业试跑）
3. 整体替换的选源列表
4. 维护页/其它地方若还有同款卡，一并收进来

组件入参：名字、备注（空则显示「没有备注」）、状态（运行中 / 已停止 / 故障 / 正在启动 / 状态未知）、状态原因、缺包数、配置 home 档（共用 / 独立 / 试跑 / 读不到）、不可用原因（可空）、标记（在跑 / 当前配置 / 已选 等）、点击回调、id 前缀、读屏标签。技术细节（home 路径、缺包名字、原因全文）只进悬停，不进正文。

### 25.2 卡片里显示什么

三行，固定高度 96px，一律单行省略：

1. 名字 + 状态词（状态词紧跟名字，同一行）
2. 备注（没有就写「没有备注」）
3. 缺包数 + 配置 home 档（两个短标记同一行）

不可用时第 3 行换成原因（单行省略，全文进悬停）。**不再显示**：缺包清单、home 路径、上次启动时间。

### 25.3 不许出现的排版问题

- 卡片内任何文字不换行：`white-space: nowrap` + 超长省略号；「运行中」「缺 6 个包」「配置 home：共用」这类短标记必须一行。
- 列表容器 `overflow-x: hidden`；卡片 `overflow: hidden`；任何一张卡的 `scrollWidth` 不得超过 `clientWidth`。
- **状态灯挂在图标右上角**（图标容器 `position: relative`，灯 `top: -3px; right: -3px`），不再相对整张卡定位，也不许溢出卡片。
- 四个调用点的卡片高度必须一致（96px），不允许某个页面被内容顶高。

### 25.4 框头那句固定

新建实例框的说明句不再随复选框换字，固定为：

`从现有的某个配置复制一个，或者是创建一个全新的`

复选框只影响卡片区锁不锁、名字格引导要不要显示，不改这一句。

### 25.5 验收

1. 新建实例框：列表无横向滚动条（`scrollWidth == clientWidth`），四张卡里没有任何文字折行，卡高全 96
2. 勾上 / 勾掉：框头那句文字完全不变
3. 状态灯在图标右上角，不溢出卡片（卡片 scrollWidth 不因它变大）
4. 维护页「选择配置」与整体替换选源：卡片结构、高度、悬停与改后一致；点选、禁用、当前配置标记照旧
5. 390 宽下三处都没有横向滚动，卡片仍单列
