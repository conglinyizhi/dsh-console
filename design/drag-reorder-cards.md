# 首页拖动：落在哪张卡上就占哪一格

状态：规格。实现按它做。只改前端（view_overview / state / app / dom / app.scss），后端不动。

## 0 现在的问题

落点按「指针与最近那张卡的中心线」算：压在卡片下半部分就会插到它**后面**。手盯着某张卡，
占位块却出现在旁边一格，看起来像没跟上手。用户要的是卡槽语义。

## 1 目标口径

```
指针在某张卡上   = 被拖的卡占这一格；这张及其后面的各往后顺延一格
指针在栅格下方   = 最后一格
指针在栅格上方   = 最前一格
```

- 不再按中心线上半 / 下半分叉。卡槽就是格子，一格一个意图。
- 指针落在两张卡之间的空隙时，取**中心距离更近**的那张（空隙只有 12px，不引入新的分界规则）。
- 指针在被拖的那张自己身上：落点就是它现在这格，松手等于没动（不发请求）。

## 2 末尾那一格

- 栅格末尾放一块**不可见的落点区**：绝对定位，不参与布局（不改变卡片位置），
  覆盖最后一行下方到栅格底、以及栅格宽度内的区域；只在拖动期间存在。
- 指针进这块区域 = 最后一格。
- 最后一行正好铺满时，指针压在最后一张卡上也算最后一格（等价，不冲突）。

## 3 不变的东西

- 跨组不落（两组是语义，不合并）
- 拖动期间页面滚过就作废，顺序一个字节不动
- 窄屏（< 726px）不启动拖动
- 键盘换位 Ctrl+↑/↓ 走同一条提交路径、同一个落点算法
- 落位写回仍走 set-row-order 一次整份顺序

## 4 验收（无头浏览器实测，不看代码）

1. 4 张卡排两列：拖第 1 张到第 3 张身上，松手后顺序 = 1 张原位置被第 3、4 张顶上来，被拖的落在第 3 张那格。
   （用 order.json 的最终内容与屏幕上的顺序两边对数）
2. 拖到栅格下方空白区，松手后落在最后一格。
3. 拖到被拖的那张自己身上，松手顺序不变、没有请求发出。
4. 拖到另一组里，松手不动。
5. 键盘 Ctrl+↓ 两次，顺序与拖动同一条路径。
6. 窄屏 600px 下按住拖动，页面滚动正常、顺序不变。
