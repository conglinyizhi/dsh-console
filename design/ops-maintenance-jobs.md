# 维护：作业台与「升级 dsh」

状态：名字已定（侧栏第二项「维护」）。规格第二版：**验收由用户自己试，程序只负责把新版跑起来、记下结论、按结论迁移或回滚。**

## 0 一句话

侧栏在「实例总览」下面加一项**维护**。里面是一张**作业台**：一项作业 = 一组按顺序做、每步有检查、失败能退回、关掉页面明天还能接着做的步骤。

第一条作业：**升级 dsh** —— 锁定当前版本当回滚锚，装新版本，把新版本起成一只**能真用的实例**给用户试；用户说好用就迁移到新版，说不好用就回滚，旧版本最后才清理。

## 1 为什么是「作业」不是「流程」

作业有状态（现在到第几步）、有检查（每步的结论要留下）、有回滚点、能中断恢复。流程没有这些。
界面用大白话，内部术语不进正文。

## 2 装在哪

- 侧栏第二项：`维护`，路由 `/maintenance`
- 页面：作业列表（一张卡：标题、状态、第几步、开始于、一句话结果）+ 展开后的步骤表
- 空态：`还没有作业。/ 一条作业是按顺序做完的事，中间停止也不会丢进度。`

## 3 状态与落盘

- 目录：`$XDG_STATE_HOME/dsh-console/jobs/`（与 dsh-pin.json 同一套口径，走 `@store.state_paths()` 加一个 `jobs` 字段）
- 一份作业一个文件：`<jobId>.json`，jobId = `<kind>-<epoch秒>`
- 形状（字段名即 JSON 键）：

```json
{
  "id": "upgrade-dsh-1791028571",
  "kind": "upgrade-dsh",
  "title": "升级 dsh",
  "createdAt": "…", "updatedAt": "…",
  "step": "lock|install|trial|verdict|commit|rollback|cleanup|done|aborted",
  "steps": [
    { "key": "lock", "state": "passed|failed|skipped|not-run|running", "at": "…",
      "note": "一句人话", "evidence": {} }
  ],
  "rollbackAnchor": { "dir": "…", "version": "0.2.1-rc.2" },
  "target": { "version": "0.2.2-rc.1", "dir": "…" },
  "trial": { "port": 8500, "pid": 1234, "url": "http://127.0.0.1:8500/", "profile": "web", "startedAt": "…" },
  "verdict": { "value": "good|bad", "at": "…", "note": "" },
  "commands": [ { "at": "…", "argv": ["pnpm","add","-g","@deepseek-ai/dsh@0.2.2-rc.1"], "result": "…" } ]
}
```

三条硬口径：

1. **五档状态**：`running / passed / failed / skipped / not-run`。**「没验到」必须是 skipped 或 not-run，绝不能写成 passed**。
2. 写入一律原子（沿用 `@fsx.write_text_atomic`）。坏文件读不出来 → 列表里那条显示「记录读不出来」+ 原因，不吞。
3. 控制台重启后作业还在，状态从文件恢复，不靠内存。

## 4 动作（都走 POST /api/local/action，守卫照旧）

| 动作 | 参数 | 做什么 | 失败码 |
|---|---|---|---|
| `job-start` | `{"kind":"upgrade-dsh","version":"<目标版本>","profile":"<试跑用哪只 profile>"}` | 建作业，**第 1 步 lock 立刻做**：把当前生效的那份 dsh 记为回滚锚（只记在作业里，不动 dsh-pin.json） | `bad-params` / `job-exists`（同一 kind 已有未结束的） / `not-found`（profile 不存在） |
| `job-install` | `{"id":"…","confirm":false}` | `confirm:false` = **预演**：回出确切命令、它会不会覆盖正在跑的那份，不执行；`confirm:true` = 执行 `pnpm add -g @deepseek-ai/dsh@<版本>`，输出尾部记进 commands，并把新版候选目录记进 target | `not-found` / `conflict`（不在 install 步）/ `spawn-failed` |
| `job-trial` | `{"id":"…"}` | **把新版起成一只真用的实例**：新版目录 + 用户真实 DSH_HOME + 用户选的 profile + 空闲端口，等监听 + 签名通过；记 pid / port / url / token（读得到才记）进 trial。**不判定好坏**。跑完 step=trial→verdict | `conflict`（不在 trial 步，或已有一只试跑实例在跑）/ `spawn-failed` |
| `job-verdict` | `{"id":"…","verdict":"good"|"bad"|"later"}` | good → 停试跑实例、把 dsh-pin.json 指到新版、step=commit；bad → 停试跑实例、把 dsh-pin.json 恢复成开工前的状态（原来没指定就删掉）、step=rollback；later → 只记录，什么都不动，step 留在 verdict | `bad-params` / `conflict`（不在 verdict 步） |
| `job-cleanup-preview` | `{"id":"…"}` | 列出「清理后会删掉什么」：旧版包目录、占多大、有没有在跑的实例用它 | `not-found` |
| `job-cleanup` | `{"id":"…","confirm":"DELETE"}` | 删旧版包目录（硬删，只删这一份）。没带 confirm 一律拒 | `bad-params` / `conflict` |
| `job-abort` | `{"id":"…"}` | 中止作业：停掉试跑实例（如果在跑），保留记录与已做步骤，step=aborted | `not-found` |

口径：

- 会动系统的一律先预演（install / cleanup），确认才执行。
- **试跑实例不被作业自动收掉**：用户可能要试一阵。作业在 verdict 步时，页面要显示「试跑实例还在跑」与它的地址，并防止再起第二只。
- 回滚 = 停试跑实例 + 恢复开工前的版本指定。**不删除新装的那份**（删不删是清理那一步的事，用户没要求回滚时连它一起删）。
- 作业记录里出现的路径与命令原文只进悬停/详情，不进正文。

## 6 硬约束

- 不进正文的：目录路径、命令原文 —— 进悬停或「详情」，正文只给结论
- 颜色不作唯一信号（三色灯 + 文字状态词）
- 验证时**不许真跑 `pnpm add -g`**，也不许真删任何包目录：install / cleanup 只验预演与拒绝路径
- 验证时**不许在真实 DSH_HOME 上起试跑实例**：那是用户点才做的事；验证用临时 DSH_HOME + 临时的同名 profile
- 不许跑 moon fmt；构建口径照旧（各自 .sandbox/moonhome + MOON_CC/MOON_AR/MOON_LD）
- 不提交 git
- 不要动 5390；隔离验证用 5391 + 临时 XDG_STATE_HOME + 临时 DSH_HOME

## 8 第二版增补（用户口径）

### 8.1 维护页用满可用宽度

现在维护页套的是 `.dsh-page`（最大宽度 920px、贴左），1637 宽的窗口里右边空掉一大片。
维护页改成用满内容区宽度：`max-width: none`，只保留内边距。作业卡与步骤表跟着铺开。
关于页与设置页仍用 `.dsh-page` 的窄栏（散文与表单，一行太长反而难读），不跟着改。

### 8.2 目标版本：可搜索，允许自己写

- 目标版本控件换成**可搜索的下拉**：输入即过滤，列出候选（版本号 + 已装 / 最新 / 预发布 标记）。
- 候选来自 `GET /api/local/dsh-releases`（三源顺序见 design/dsh-release-sources.md）。
- 列表里没有想要的版本时，输入框里继续写就是**自定义版本**：给一行提示「列表里没有 <输入>，可以直接用这个版本」，点「用这个版本」按它开工。
- 自定义版本不做存在性校验（控制台不猜远端有什么），装不上由安装那一步如实报失败。

### 8.3 试跑用 profile：不可用的要说原因

- profile 下拉列出本机全部 profile，每条后面可以带状态：
  - **可用**：没有附加标记。
  - **不可用**：置灰不可选，原因写在悬停与下方一行提示里。
- 判据（只看事实，缺包不算不可用）：
  1. 目录读不到 / 没有 `package.json` → 不可用：「读不到这只 profile 的配置」。
  2. `dsh.profile.bundles` 里没有 `@deepseek-ai/dsh-web-app` → 不可用：「这只 profile 起的是命令行型（没有网页入口），试跑要能起网页实例的配置」。
  3. 缺包（`bundles.missing` 非空）**仍然可用**，但旁边注明「缺 N 个包，可能起不来」。
- 正在跑的那只 profile 也可以用（见 8.4），不被占用。

### 8.4 试跑用一次性 home，不占正在用的那份

（口径变更：不再在同一个 home 里复制临时 profile，改成一次性 home，见 design/deep-home-isolation.md 第 6 节）

1. 建 `~/.dsh-homes/trial-<作业 id 末 6 位>/`，按隔离 home 的铺法复制 profile 配置、软链 node_modules、凭证只写路径；
2. 用这份 home 起测试实例，`trial.home` 与 `trial.homeKind="trial"` 记下来；
3. 停止试跑（good / bad / trial-stop / abort）时删掉这个一次性 home。

用户可见的一句话放在试跑那一块：
`试跑跑在一次性的 home 里，你平时那份配置与状态都不动，作业收尾时它会被删掉。`

### 8.5 硬约束补充

- 临时配置只准建在 `<DSH_HOME>/profiles/` 下，名字固定前缀 `trial-`；删除时只删这个名前缀的目录。
- 软链只指向源 profile 的 `node_modules`，不复制、不移动用户的东西。
- 验证时同样不许在真实 `~/.dsh` 上建临时配置：用临时 DSH_HOME 验。

## 10 第四版：版本弹层、配置侧栏、后端预热

### 10.1 不让用户等

控制台进程一起来就在后台拉一次版本列表（异步，不阻塞启动，也不阻塞任何 GET）。结果存进程内缓存：

- `GET /api/local/dsh-releases` **立刻返回**缓存，形状加三格：`state`（`loading` / `ready` / `failed`）、`fetchedAt`、`stale`（超过 10 分钟为 true）。
- 缓存为空时返回 `state:"loading"` 与空列表，同时确保后台正在拉。
- 缓存过期或为空时，GET 不等待，只在后台再发起一次。
- 拉取仍然照 design/dsh-release-sources.md：三源并发、各 6 秒超时、github → npm → mirror 优先。

### 10.2 目标版本换成弹层

- 表单里那一格不再是常驻候选列表，改成一行「当前选择」+ 一个「选择版本」按钮；没选时显示「未选择」。
- 点按钮开弹层（居中对话框，复用现有 dialog 外壳）：
  - 顶部搜索框，输入即过滤，最多 20 条，余下写「还有 N 条匹配，继续输入缩小范围」
  - 每条带 已装 / 最新 / 预发布 与悬停依据
  - 列表里没有的：写「列表里没有 <输入>，用这个版本」，点它把输入当版本选中
  - 底部小字：来源、拉取时间、以及「正在重新拉取」或失败原因
  - 选中后回填表单并关闭弹层；Esc 关闭；焦点先进搜索框
- 弹层里 `state:"loading"` 时显示「正在拉版本列表」而不是空列表；`failed` 时显示原因并允许直接手写版本。

### 10.3 试跑用配置换成右侧侧栏

- 表单里那一格改成「当前配置」+ 「选择配置」按钮。
- 点按钮开右侧侧栏（与实例详情抽屉同一套外壳），里面**复用总览的卡片样式**列出本机全部 profile：
  - 可用：整卡可点，显示名字、缺包数（有就写「缺 N 个包，可能起不来」）、home 归属
  - 不可用：整卡置灰不可点，卡上写明原因（读不到这只配置 / 这只配置起的是命令行型，没有网页入口）
  - 点选后回填并关闭侧栏；Esc 关闭；焦点进侧栏后先落在第一张可点的卡上

## 12 第六版：版本改成表格侧栏，配置侧栏照总览来

### 12.1 版本选择也放进右侧栏

目标版本不再用居中弹层，改成右侧栏，与「选择配置」用同一套外壳（右侧滑出、Esc 关、焦点进搜索框）。
表单里仍是「当前版本 + 选择版本」按钮。

### 12.2 版本侧栏里是一张表

列：版本 / 标记 / 发布时间。

- 标记按档上色（颜色不是唯一信号，文字必须同时在场）：
  - `当前在用`：这一版就是现在生效的那份 dsh（绿色）
  - `已安装`：本机装着这一版（蓝色）
  - `正式发布`：版本号不带预发布后缀（中性色）
  - `预发布`：版本号带 -rc / -alpha 等（琥珀色）
  - 一版可能同时有多个标记，按上表顺序排，最多显示两个，其余进悬停
- 发布时间：后端要给出每版的发布时间。GitHub 用 release 的 `published_at`，npm 与国内镜像用 registry 的 `time[版本]`；没有就写 `不知道`，不拿拉取时间顶替。

### 12.3 简单过滤与排序

- 过滤（多选 chip）：`全部` / `已安装` / `正式发布` / `预发布`。默认全部。
- 排序：`版本从新到旧`（默认）/ `从旧到新` / `按发布时间`。
- 过滤与排序都在前端做，不重新请求；顶部搜索框仍然生效，三者叠加。
- 结果为空时写 `没有符合条件的版本`，并保留「写一个自定义版本」那一行。

### 12.4 配置侧栏照总览来

现在的配置卡只有名字、缺包数与 home，缺备注与运行状态，顺序也与总览不一致。改成：

- 数据来源与总览同一套行：先运行中分组，再停放分组；组内按 order.json 的顺序。
- 每张卡显示：名字、备注（有就显示一行，没有写 `没有备注`）、状态灯 + 状态词、缺包数、home 归属；不可用的卡另写原因。
- 运行中的卡带 `在跑` 标记；当前选中的卡带 `当前配置` 标记。
- 不可用的卡仍置灰不可点。

## 13 两处按钮语义

### 13.1 停用行不再亮「复制访问地址」

停用的行 `url` 是占位串（`已停用，无法访问`），抽屉里那颗「复制访问地址」还亮着，点下去把这句话写进剪贴板。

- 行上带一个明确的「有地址可复制」标记，只有真在跑、地址不是占位串的行才是真。
- 没有地址时按钮置灰，悬停写 `这只没在跑，没有可复制的访问地址`。
- 复制动作自己也拦一道：没有地址就不碰剪贴板，回执写 `没在跑，没有访问地址可复制`。

### 13.2 删除按钮的 Shift 语义

- 抽屉里那颗「删除」：按住 Shift 时即时变红、文案换成 `彻底删除`。Shift 状态由文档级 keydown / keyup 打标记，CSS 直接换色换字，不走状态回环。
- 回收站关掉（`safety.deleteToTrash=false`）时始终红色、始终 `彻底删除`，不管按没按 Shift。
- 点下去那一刻把当时是哪种模式记进确认框：标题 `彻底删除 <名字>？` 或 `删除实例 <名字>？`，正文分别是 `删除后无法恢复。` 或 `删除后移入回收站，可以捞回来。`，确认键在彻底删除时用红色。
- 确认时按记下的模式发请求（彻底删除带顶层 `confirm:"DELETE"`），不靠事后猜。

### 13.3 文案（待审）

- `彻底删除` / `删除`
- `彻底删除 <名字>？` / `删除实例 <名字>？`
- `删除后无法恢复。` / `删除后移入回收站，可以捞回来。`
- `这只没在跑，没有可复制的访问地址` / `没在跑，没有访问地址可复制`
- 悬停：`按住 Shift 是彻底删除，不进回收站` / `回收站没开，删除就是彻底删除`

不用破折号。
## 14 全局提示总线

目标：**动作结果**只有一条出口，不管在哪一页触发、当时在哪一页，都看得见。**读取失败**仍留在页面原位（它解释的是「这一块为什么是空的」）。

### 14.1 模型

Model 里把这几格合成一条：

- 删：`act_notice` / `act_notice_ok` / `act_notice_hint` / `act_notice_hint_for`、`settings_feedback` / `settings_feedback_ok`、`dsh_pin_notice` / `dsh_pin_notice_ok`、`releases_refresh_error`
- 加：`notice : Notice?`，形状 `{ seq, ok, text, hint, at }`；`seq` 每次自增，用来重开 toast 计时与判断「这条提示还是不是当前那条」

成功与失败都写进这同一条出口：

- 成功：底部 toast，3.5 秒后淡出（沿用现有 `flash_toast` 的视觉与计时）
- 失败：常驻提示条，直到下一条动作替换它（不自动消失）
- 鼠标停在提示上时不消失（沿用现有规则）

### 14.2 渲染

- 外壳里只渲染一次，所有页面共用；不要每页各来一份。
- 位置与层级：提示条在内容区底部居中，**盖在抽屉与侧栏之上**，但在确认框之下。抽屉、侧栏、确认框三种状态打开时都要验证它不被挡住、也不挡住关键按钮。

### 14.3 接线点

- 总览：动作成功 / 失败、复制失败、打开 Web UI 失败，全部走这条出口
- 设置页：保存成功 / 失败
- 关于页：切版本成功 / 失败
- 维护页：开工、预演、安装、试跑、判定、切版、清理、中止的回执照旧写进作业卡（那是历史记录），**同时**发一条全局提示
- 版本侧栏的「重新拉取没成」也走全局提示；侧栏底部只保留来源与拉取时间

### 14.4 不许出的问题

- 同一句话出现两次（页面内一份 + 全局一份）。迁移时每一处只留一处。
- 读取失败被并进全局提示：那是两回事，原位保留。
- 切页面后提示消失：成功 toast 允许随页面切换自然过期，失败提示要跨页面存活。

### 14.5 验证

1. 在总览对停用的行点「查看日志」（会失败）→ 一条全局提示出现，切到设置页与关于页仍看得见（停用行的复制按钮是 disabled，浏览器不给它 click，这条按「查看日志」这个失败源验）
2. 在关于页切版本成功 → 底部 toast 出现，3.5 秒后自己消失
3. 抽屉打开时触发一次成功与一次失败，提示不被抽屉挡住，也不挡住抽屉里的按钮
4. 维护页点「重新拉取」造一次失败（用坏 URL 的临时构建或注入）→ 全局提示出现，侧栏底部不再重复
5. 全站渲染后的文案扫描：同一句话不出现两处（作业卡「一句话结果」与展开后步骤行里同一句是规格要求的摘要，不算重复，扫描时排除）

不用破折号。

### 14.6 落定口径（2026-10-19）

- 维护页：全局提示只说结论，作业卡里写细节（命令、包目录、输出尾部）；不把同一句在两处各写一遍。作业卡那句「一句话结果」与步骤行同句属于摘要，保留。
- 停用行的复制按钮保持 disabled：它没有可复制的内容，不给它一个「点了先失败一次」的入口。
- 「正在保存 …」这类过程播报不再发，只留结果。
