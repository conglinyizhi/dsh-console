### 2. 访问地址那一栏：停止时说实话，且不出现 key
- 状态：**已完成**（`107116e`）—— 已停止卡显示「已停用，无法访问」；那一栏的悬停改成只说这一行自己，**不再提令牌**；带令牌的地址只在「打开 Web UI」与菜单「复制带令牌的地址」
- 使用者原话：「这个访问地址让它在没有启动的时候就显示该实例已停用，无法访问；然后在运行的时候，你就直接提供运行端口就好了，这个位置不提供 key」
- 改法：已停止 → `已停用，无法访问`（现在是 `—`）；运行中 → `127.0.0.1:3080`（去掉 scheme 与令牌）；**这一栏的悬停不再讲令牌**
- 令牌的去处只剩：卡上「打开 Web UI」+ 行菜单「复制带令牌的地址」
- 为什么等着：与第 1 条改同一批文件（`state.mbt` / `view_overview.mbt`），不能并行改

### 3. 路由管理：刷新后回到原来那一页（含设置的细分分组）
- 状态：**进行中**（worker `403b3120`，与第 4 条同一批做）
- 使用者原话：「Vue Router 那种引擎都会实现路由管理，页面刷新之后也会展示原本就打开的页面，那个好像是 history/hash 技术……把这个技术应用上，避免刷新之后是一个其他的页面，也包括设置的细分页面」
- 要求：切换页面（实例总览 / 日志 / 设置 / 关于）与**设置页的五个分组**都要进 URL；刷新后落回同一处；浏览器前进后退可用
- 注意：日志页如果带「来源=某实例」，那也算页面状态的一部分（要不要进 URL 待定，倾向进）
- 不许用需要 Node 的构建链；纯前端实现（`history.pushState` / `hashchange` 或二者结合）

### 4. 加载态：数据还没到 ≠ 没有数据
- 状态：**进行中**（worker `403b3120`）
- 使用者原话：「在没有数据，就是刷新之后有一个短暂的数据加载，但是数据只是还没到，它不是真的没有数据，但是在我们这它只是一个简单的空数据的提醒，应该在那放一个加载的界面」
- 现状：刷新后接口还没回来时，界面直接摆出空态（“没有实例”那种）✗ 会让人以为真没有
- 改法：三个读数（runtime / profiles / instances）**没回来之前显示加载态**（骨架或“正在读取…”）；**空态只在读数确实为空时出现**
- 日志页同理（日志没读完 vs 日志为空）

### 5. 启动实例成功后自动开标页（占位页模式）
- 使用者原话：「启动某个实验 profile 的时候，我们能通过 webui 来启动新的标签页吗？因为首次握手需要控制台打印的 key」
- **硬约束**：`window.open` 必须在用户手势的同步栈里 ✗ 启动要等约 2.5 秒，等响应回来再调用会被弹窗拦截器拦掉
- 方案 A（首选）：点「启动」的同一手势里同步开占位页 `window.open('', '_blank')` → 拿到 `webUrl` 后 `w.location.href = webUrl`；失败/无令牌/被拦 → `w.close()` 并说明原因，不留白页
- 方案 B（兜底）：启动成功的提示条里带「打开 Web UI」按钮（新手势，一定不被拦）

### 6. `audit.jsonl` 滚动
- 现状：只追加不轮转（契约如此），跑几个月会变成几 MB
- 改法：超 N MB 滚动保留最近 M 条；轮转本身也要记一条（不然审计有断口）
