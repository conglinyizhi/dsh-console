### 2. 用 `pgrep -f` / `pkill -f` 杀进程时，命令里不能出现那个进程名
- 栽过两次：`pkill -f '[d]sh-console-backend'` 与 `pgrep -f 'debug/build/dsh-console-backend.exe'`
  **都匹配到了执行它们的那个 shell 自己** —— 方括号只保护 pkill 那一行，保护不了整条命令行 ✗
- **规矩**：停后台进程用 `job_kill <job_id>`（我起的都有句柄）✓ 或按端口/PID 精确杀 ✓
  **绝不在同一条命令里既写进程名又用它去匹配进程** ✗

### 3. 判定要测到「模式的边界那一格」
- 菜单截断那个 bug 从我的验收下溜过去，因为探针只测**第一张卡**的菜单（离底边远，永远绿灯）
- **规矩**：同一模式有多处实例时，至少测**第一处与最后一处** ✓（现在「底部卡的菜单不出屏」就是补这个的）

### 4. 入口坏掉时判定会「因为没东西所以全绿」
- 对话框那四条曾经在入口失效时全绿（没框所以框关着）✗
- **规矩**：一组判定前面要加一条**前置条件判定**（「入口能开框」），前置不成立时后面一起红 ✓

### 5. 数据一变就假红的判定同样是坏的

- **规矩**：期望值从**实时数据**推（在跑实例数、当前行数），推不出就如实记为**信息**而不是失败 ✓

### A. 加载态那四句可见文案删掉，只留 sr-only 一条
使用者原话：删掉这些东西，骨架屏就已经代表加载状态了。
做法：把两句标题与两句说明从可见位拿掉，改成视觉隐藏（sr-only）但保留 role=status 与 aria-live=polite。
理由：骨架屏对屏幕阅读器等于空白，那几块方块它读不出来。DOM 里留一条不占像素的状态说明，屏幕上一个字都不占。
分组标题的当前运行的实例 (…) 与 已停止的实例 (…) 留着，那是读哪一组的定位，不是加载态。

### C. 抽屉里问题提示的高度上限（本轮新加）
使用者原话：这种已经知道的问题就换成一个占一行空间的卡片提示用户，同时，对于未知的问题，
最多允许展示两行，避免下拉太多高度影响用户操作习惯。
背景：profile 健康那一节现在把 11 个缺包名整串摊开，占掉大半屏。

两类分开处理：
- 已知且可枚举的问题（例如缺 N 个包）：正文压成一行，例如 缺 11 个包；完整清单收进悬停。
- 未知问题（自由文本，例如后端报回来的错误串）：正文最多两行，超出省略号；完整内容收进悬停。
- 两类都不许把抽屉撑高到影响操作；悬停里保留全文，信息不丢。
